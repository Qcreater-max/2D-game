# 像素勇士:暗影征途

一个运行在浏览器里的 2D 横版像素动作游戏。玩家穿过 5 个主线关卡,在铁匠铺升级装备,最后挑战暗影巫师。另有无尽模式、地下洞穴和隐藏房间。

所有游戏规则都由 Python 后端计算,浏览器只负责采集按键和绘制画面。

## 快速开始

**在线试玩:[https://qcreater-max.github.io/2D-game/](https://qcreater-max.github.io/2D-game/)** — 不用下载、不用装 Python,浏览器打开就能玩。默认是离线模式(引擎已经移植成 JS,在本地运行),手机浏览器也能玩。

想在本地跑 Python 服务器版本,需要 Python 3.13(开发和测试使用的版本)。

```
pip install -r requirements.txt
python server.py
```

然后用浏览器打开 `http://127.0.0.1:8080/`。

`server.py` 的可选参数:

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 监听地址。默认只有本机能访问 |
| `--port` | `8080` | HTTP 和 WebSocket 共用这一个端口 |
| `--max-players` | `8` | 同时在线人数上限 |
| `--max-per-ip` | `3` | 单个 IP 的连接数上限 |
| `--trust-proxy` | 关 | 在反向代理之后运行时使用,按 `X-Forwarded-For` 识别客户端 IP |
| `--allowed-origin` | 不检查 | 允许发起 WebSocket 的页面来源,可重复 |

## 游戏玩法

### 操作

| 功能 | 按键 |
| --- | --- |
| 移动 | `A` / `D` 或 `←` / `→` |
| 跳跃 | `W` / `↑` / `空格`(松开按键可提前结束上升,控制跳跃高度) |
| 穿过单向平台 | 站在平台上按住 `S` / `↓`,再按跳跃 |
| 攻击 | `J` 或鼠标左键 |
| 互动 | `E`(宝箱、铁匠、传送门、隐藏房间) |
| 进入地洞 | 站在洞口,按住 `S`,再按 `E` |
| 背包 | `I` |
| 战绩 | `Tab` 或 `C` |
| 返回 / 关闭 | `Esc` |
| 菜单和面板 | `↑` `↓` 选择,`←` `→` 切换页签,`Enter` / `空格` / `J` 确认 |

触屏设备会自动显示虚拟按键:左右移动、跳、攻、互动、背包。

### 鼠标瞄准

使用弓、火焰杖这类远程武器时,按住鼠标左键,弹道会朝鼠标所在位置飞出,角色也会转向鼠标一侧。松开左键后,回到按朝向发射。近战武器不受影响。

### 游戏模式

**冒险模式**:按顺序通关 6 个关卡。清空一关所有敌人后,走进传送门会自动进入下一关,并获得额外经验。还有敌人时也可以按 `E` 强行进入,但拿不到通关奖励。进入下一关会恢复 30% 的最大生命。死亡后可以从当前主线关卡的起点重新挑战。

**无尽模式**:在一个一屏宽的竞技场里,敌人一波接一波从两侧涌入。死亡即结束,回到主菜单,成绩记录为最高波数。

### 成长

- 击杀敌人获得经验和金币。升级时最大生命 +15,生命回满,攻击力每级提升 6%。
- 升级所需经验每级乘以 1.45。
- 金币在铁匠铺购买武器和盔甲。每个主线关卡都有铁匠铺(前 5 关在靠近传送门的位置,首领关在最左边),无尽模式的竞技场中央也有一个。地下子关卡和隐藏房间里没有。
- 宝箱里可能是金币、武器或盔甲。如果开出来的装备比当前的强,会自动装备;已经拥有的,折算成 30 金币。

### 探索要素

- **木箱**:近战或远程攻击都能打碎,需要打 2 下。打碎后 55% 掉金币,25% 掉回血,其余为空。
- **地洞**:部分关卡有。进入后是地下子关卡,有额外的宝箱和更强的怪物。回到地面时,宝箱有没有开、怪物死没死、木箱碎没碎,都会保留。
- **可疑裂墙**:攻击几次后墙会破开,露出通往隐藏房间的入口。房间里有一个宝箱,通常是稀有装备。
- **移动平台**:熔岩洞窟里的平台会左右摆动,站在上面会被带着走。

### 危险物

| 类型 | 伤害 | 元素 | 说明 |
| --- | --- | --- | --- |
| 尖刺 | 最大生命的 12% | 物理 | 接触后被弹起 |
| 岩浆 | 最大生命的 20% | 火 | 接触后被弹起,熔岩甲可以大幅减免 |
| 毒沼 | 最大生命的 4% | 物理 | 站在里面持续掉血,每 40 帧一次 |

危险物不受盔甲的百分比减伤影响,但元素抗性仍然生效。

### 坠落

- **掉进深坑**:扣最大生命的 15%,然后被送回最近的安全地面。生命不够就会死亡。
- **摔伤**:从最高点落到地面的落差超过 130 像素时,超出的部分每像素扣最大生命的 0.16%,最多扣 45%。摔伤不会致死,最低剩 1 点生命。跳起再落回原地不算摔伤。

## 战斗系统

### 伤害公式

对敌人造成的伤害,按下面的顺序计算:

1. 基础伤害 = 武器伤害 × 等级加成
2. 元素倍率:命中敌人的弱点元素 ×1.5,命中抗性元素 ×0.5
3. 暴击(10% 概率):×2
4. 敌人处于眩晕状态:×1.5
5. 减去敌人的固定防御,但最终伤害不低于上述结果的 30%

玩家受到的伤害 = 原始伤害 × (1 - 盔甲减伤%) × (1 - 元素抗性%),最少 1 点。受伤后有短暂的无敌时间。

### 元素

| 元素 | 效果 |
| --- | --- |
| 物理 | 无特殊效果 |
| 火 | 灼烧 3 秒,每 0.5 秒一跳,每跳为命中伤害的 20%(至少 2 点)。对火抗性敌人无效 |
| 冰 | 减速 2 秒,移速减半。首领免疫 |
| 雷 | 电弧跳向 110 像素内最近的另一个敌人,造成 50% 伤害,只跳一次。**无视盾卫的格挡** |

### 手感

命中会让世界短暂停顿几帧,暴击和弱点命中停得更久。受伤、爆炸和暴击都有屏幕震动。命中有火花和冲击环特效,伤害数字会飘出。

### 暗影巫师

首领战只有一个房间,巫师按下面的循环行动:

1. **悬浮弹幕**:在空中发射火球,普通状态一次 3 发,生命低于一半(狂暴)后一次 5 发,发射间隔也更短。
2. **蓄力**:向玩家上方移动。
3. **砸地**:垂直下落,落地时向两侧释放雷属性冲击波。狂暴后每侧会释放两道不同速度的冲击波。
4. **硬直**:砸地后僵住一段时间,这是主要的输出窗口。狂暴后硬直时间更短。

冲击波可以跳过去。击败巫师即通关。

### 无尽模式的波次

- 每波敌人数量 = min(14, 3 + 波数 × 2)。
- 第 1 波起:史莱姆、哥布林。第 2 波加入弓手、自爆虫。第 4 波加入野猪、骷髅。第 6 波加入盾卫、蝙蝠。
- 敌人生命每波增加 12%,金币奖励每波增加 5%。
- 清完一波后有奖励金币(20 + 波数 × 8),并恢复 25% 最大生命,约 2.5 秒后开始下一波。

## 技术架构

### 总体设计

```
浏览器 (client.js)  ──按键 / 鼠标瞄准 (JSON)──▶  server.py  (HTTP + WebSocket,同一端口)
       ▲                                              │
       └──────── 每帧状态 (JSON) ◀──────── GameEngine.tick()  (60 帧/秒)
```

核心原则是**服务端权威**:所有物理、战斗、AI、关卡流程、数值计算都在 Python 里。浏览器只发送"哪些键被按住",并绘制收到的状态。这样客户端无法通过篡改来作弊。

### 后端

引擎 `GameEngine`(`game_engine.py`)由 4 个 Mixin 拼起来,每个 Mixin 管一块规则:

| 模块 | 职责 |
| --- | --- |
| `combat.py` | 玩家攻击、伤害结算、元素状态、掉落、升级、特效 |
| `enemies.py` | 敌人工厂和通用 AI(巡逻、追击、远程、冲锋、格挡) |
| `boss.py` | 暗影巫师的行为状态机 |
| `world.py` | 危险物、移动平台、木箱、地洞、隐藏房间、无尽模式 |

其他模块:

- `physics.py`:碰撞和移动。支持实心地面和单向平台(只能从上方落上去,可以从下方穿过)。
- `levels.py`:关卡数据,用声明式的字典描述地面、平台、敌人、宝箱、危险物等。
- `game_data.py`:所有数值表(武器、盔甲、敌人、元素、物理参数)。

几个实现细节:

- **按键边沿检测在服务端做**:菜单、背包等一次性操作不需要客户端定时发脉冲。
- **跳跃手感**:提前输入缓冲 6 帧,离地后还有 6 帧的宽限(coyote time)。
- **命中停顿**:世界暂停几帧,但不会吞掉刚按下的跳跃。
- **关卡栈**:进入地洞或隐藏房间时把当前关卡状态压栈,返回时恢复。
- **静态数据与动态数据分开**:平台、传送门等换关时才发送一次(`level` 消息),每帧只发变化的内容(`state` 消息)。武器、盔甲、怪物图鉴由服务器通过 `CATALOG` 下发,前端不重复维护。

### 前端

纯 HTML5 Canvas,没有框架和构建步骤,逻辑分在几个脚本里:

| 文件 | 职责 |
| --- | --- |
| `client.js` | 输入采集(键盘、鼠标、触屏)、WebSocket 连接、主循环、画布缩放 |
| `render.js` | 主渲染:背景主题、地形、角色、武器、弹道、粒子 |
| `render_world.js` | 世界元素:危险物、移动平台、木箱、地洞、裂墙 |
| `sprites.js` | 用字符矩阵定义的像素精灵,带缓存 |
| `ui.js` | HUD、菜单、商店、背包、战绩、怪物卡片 |

画面是 960×540 的逻辑分辨率,按窗口大小等比缩放,使用 `image-rendering: pixelated` 保持像素风格。渲染出错时不会中断循环,错误会显示在屏幕顶部。

### 服务器

`server.py` 用 `websockets` 库,HTTP 和 WebSocket 共用同一端口(WebSocket 路径为 `/ws`)。

- **每个连接一局独立的游戏**:每个 WebSocket 连接创建自己的 `GameEngine`,玩家互不影响。
- **固定 60 帧/秒**:游戏循环独立于连接数,卡顿后不会疯狂补帧。
- **静态文件白名单**:只有 `index.html` 和几个 `.js` 文件可以访问,源码和 `.git` 不会泄露。
- **滥用防护**:
  - 在线人数上限和单 IP 连接上限
  - 单条消息大小上限 1 KB
  - 每连接令牌桶限流(每秒 120 条,突发 60 条)
  - 客户端接收太慢时丢弃状态帧,避免内存被积压撑大
  - 可选的 `Origin` 白名单
  - 一个玩家的引擎出错只断开这个连接,不影响其他人
- **输入校验**:鼠标瞄准坐标会检查类型、有限性和范围,拒绝 `NaN`、`Infinity` 和超大整数。弹道速度由服务端按武器决定,客户端只上报坐标,无法伪造速度。

## 通信协议

所有消息都是 JSON。

### 客户端 → 服务器

```json
{"left": false, "right": true, "jump": false, "attack": true, "aim": [640, 220]}
```

- 按键字段:`left` `right` `up` `down` `jump` `attack` `interact` `confirm` `inv` `stats` `escape`,值为是否按住。只需要发送变化的字段。
- `aim`:鼠标在画面里的位置 `[x, y]`,不瞄准时为 `null`。
- `{"need_level": true}`:请求重发关卡数据。

### 服务器 → 客户端

- `{"t": "level", ...}`:关卡的静态数据(地图宽度、静态平台、传送门、铁匠铺位置、主题、`catalog`)。换关时发送,也可以由客户端请求。
- `{"t": "state", ...}`:每帧的动态状态,包含 `game`(阶段、镜头、消息等)、`player`、`enemies`、弹道、粒子、掉落物、宝箱、木箱、飞字、特效和交互提示。
- 每个 `state` 都带 `seq`。如果和客户端当前关卡的 `seq` 不一致,客户端会请求重发关卡数据。

### 关闭码

| 码 | 含义 |
| --- | --- |
| 1013 | 服务器已满 |
| 1008 | 同一网络的连接数过多 |
| 1011 | 服务器内部错误 |

收到 1013 或 1008 时,客户端会放慢到每 10 秒重连一次。

## 测试

```
python -m unittest discover -s tests
```

测试覆盖鼠标瞄准、元素与伤害、摔伤、关卡可达性(平台间距是否在跳跃能力范围内)、阶段流程,以及服务器会话的隔离、输入校验和限流。

`tests/` 里还有一个渲染测试页面(`render_harness.html`),以及生成测试快照的脚本(`make_snapshot.py`),用来在浏览器里单独检查画面。

## 公开部署

默认只监听本机。要让别人访问,有几种方式:

- **GitHub Pages(推荐,纯前端)**:推送到 `main` 后,GitHub Actions 会自动把网页版发布到 [https://qcreater-max.github.io/2D-game/](https://qcreater-max.github.io/2D-game/)。工作流见 `.github/workflows/pages.yml`,只发布 `index.html`、脚本、图标和 `manifest.json`,`server.py` 等源码不会暴露。这是离线模式,没有 WebSocket 服务器。
- **有云服务器和域名**:把项目上传到 Ubuntu/Debian 服务器,运行 `sudo bash deploy/setup.sh 你的域名`。脚本会创建专用用户、安装依赖、注册 systemd 服务、安装 Caddy 并自动申请 HTTPS 证书,防火墙只开放 22、80、443。游戏本身只监听 `127.0.0.1:8080`,外部访问都经过 Caddy。
- **局域网**:`python server.py --host 0.0.0.0`,同一个网络里的人访问 `http://你的局域网IP:8080/`,需要在防火墙放行 8080 端口。
- **临时分享**:用 Cloudflare Tunnel 之类的隧道工具,从自己的电脑生成一个临时公网网址。电脑关机或断网就失效。

注意:

- **服务没有账号认证**,任何拿到网址的人都能玩。人数上限和限流只能防滥用,防不了有人故意占满名额。
- 每个玩家都是一个 60 帧/秒的引擎,外加每帧一次 JSON 序列化。单台服务器能撑多少人没有测过,请按服务器配置调整 `--max-players`。
- 依赖 `websockets==11.0.3` 的 API(`process_request(path, headers)` 和 `ws.transport`)。升级到更高的主版本需要修改 `server.py`。
- `deploy/` 下的文件需要保持 LF 换行,仓库里的 `.gitattributes` 已经处理了这一点。
